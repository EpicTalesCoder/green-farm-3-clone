# Green Farm 3 — Pack / BSprite map

Generated by `tools/decode_image.py` (mirror of the game's ASprite loader,
`analysis/decompiled-cfr/d.java`) on top of `tools/pack_loader.py` (mirror of
the pack stream loader, `f.java:460-560`).

```
python3 tools/decode_image.py --pack analysis/recovered/5 \
    --outdir web-port/assets/sprites/pack5 --summary analysis/pack5-summary.json
```

## Verified container format

* `<pack>` = index file: `u16 LE` block count + count × `u32 LE` offsets into a
  virtual stream = base file + `<pack>.1`, `<pack>.2`, … chunks (≤10000 B each).
* **Off-by-one (fixed in pack_loader.py):** `f.a(int)` does
  `skip(n2-k); read(); k=n2+1` — the first byte of every block region is
  DISCARDED. Block n content = `virtual[offsets[n]+1 : offsets[n+1]]`
  (last block: to end of stream). Without the +1 every block appears to start
  with a stray `0x03`.
* Each sprite block = GLLib **BSprite v5**: `u16 LE 0x05DF` + `u32 LE` flags.

## Verified BSprite layout (Green Farm 3 / this GLLib build)

Sections in order (all multi-byte fields LE):

1. **Modules** — `u16 nm`; per module one type byte:
   | type | payload |
   |------|---------|
   | `0x00` image | w (u8), h (u8) — no other fields |
   | `0xFD` marker | w, h |
   | `0xFF`,`0xFE`,`0xF8` | u32 (color/param), w, h |
   | `0xFC`,`0xFB` | u32, w, h, 2 × u16 (angles) |
   | `0xFA`,`0xF9` | u32, 4 × u16 |
   | `0xF7` | u32, u8, w, h |
2. **FModules** — `u16 tnfm`; per FM: index (u16 if flag `0x100000`, else u8),
   ox, oy (u16 each if flag `0x400`, else u8), 1 flags byte.
3. **Frame rects** (flag `0x8000`) — `u16 tnfr`, then tnfr × 4 values
   (u16 if `0x400` else u8).
4. **Frames** — `u16 nf`; per frame: nFModules (u16 if `0x800`, else u8),
   first-FM `u16`, nRects `u8` (if `0x8000`).
5. **Frame bound rects** (absent if flag `0x1000`) — nf × 4 values
   (u16 if `0x400` else u8).
6. **AFrames** — `u16 tnaf`, tnaf × 5 bytes; **anims** — `u16 na`,
   per anim u8 + u16.
7. **Image data** (flag `0x1000000`):
   `u16 pixelFormat`, `u8 nPalettes` (ALWAYS present, 1..2 observed),
   `u8 nc` (read ONCE, shared by all palettes), nPalettes × nc colors,
   `u16 dataFormat`, then per module **interleaved** `[size][data]`
   (size `u32` if flag `0x80` else `u16`; non-image modules have size 0).

Flags seen: `0x01018101`, `0x01018501` (adds `0x400`).

### Pixel formats (palette storage)
| id | format | notes |
|----|--------|-------|
| `0x5515` (21781) | A1R5G5B5, LE u16 | bit15 = opaque; **pure magenta expands to opaque 0xFF00FF** (d.java quirk) |
| `0x3203` (12803) | R3G3B2, u8 | **palette value 192 = fully transparent** |
| `0x8888`, `0x4444`, `0x1555`, `0x0565` | supported for robustness (unseen in this jar) |

### Data formats + the recovered I64RLE table
| id | format | decode |
|----|--------|--------|
| `25840` (0x64F0) | **I64RLE** | byte `v`: `index = v & tableMask`, `run = v >> tableBits`, emit palette[index] `run+1` times |
| `5632` (0x1600) | **I16** | 2 px/byte, high nibble then low nibble |

**Recovered I64RLE table:** `tableBits = bit_length(nc - 1)`,
`tableMask = (1 << tableBits) - 1` — i.e. the shared `nc` palette byte doubles
as the RLE code-length parameter. Observed (nc → bits → mask):
`49 → 6 → 0x3F`, and bits 1..5 for smaller palettes (rle_bits across pack 5:
[1,2,3,4,5,6]). Verified empirically: every module decode satisfies
`consumed == len(payload)` **and** `pixels == w*h` simultaneously (the decoder
rejects any mismatch; 0 mismatches across 2884 emitted PNGs).

## Open questions
1. **Pack 10** carries no BSprite blocks — its 21 blocks (plus packs 3/6/9/EN)
   use other formats (bytecode-like `0x32…` heads; likely MIDlet class data /
   level / text resources). Identify their loaders in `f.java` callers.
2. Skipped blocks in pack 2 (b5) and pack 11 (b12, b13): unknown sub-format,
   possibly compressed (`19 e3 01 f1` head) or table data.
3. Full frame/animation composition metadata is exported to `analysis/frames/`
   by `tools/decode_image.py --metadata-only` (schema and provenance notes in
   `FRAMES-README.md`). This preserves module/FModule/frame and animation tables,
   but does not name semantic assets or render atlases. World-data call sites still
   need to be traced before assigning a frame to a character/crop/UI element.
4. Per-module palette byte (`flag 0x4`) never observed in this jar; palette 0
   is always used. Second palettes (pack5#1 has nPalettes=2) are parsed but
   unused — expose via `--palette N` if needed.
5. The `u32` word stored in module types 0xFF–0xF7 (color for rect/fill-rect
   modules) is captured but not rendered; shape modules are skipped as
   non-image (size 0) — confirm whether the game draws them procedurally.
6. d.java's module-data section appears in CFR as two passes over a size table
   with a rewind; empirical bytes show interleaved `[size][data]`. The
   interleaved reading walks every block to an exact end, so the CFR shape is
   presumed an artifact — worth a second look if any future block fails.
